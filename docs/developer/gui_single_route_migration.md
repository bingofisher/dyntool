# GUI 单路线迁移与可靠性

稳定性：GUI 为 `Internal API`；范围解析与报告聚合为 `Private / implementation detail`。核心库继续保持独立的 `Public API`。

## 路线收敛

GUI 是当前唯一正式项目壳。Web 路线已退出：不再发行 Web 包，不再提供 Web 启动入口、依赖组或独立前端测试。历史实现通过 Git 历史追溯，不复制为另一条维护路线。原有核心库数据仍可由 Python API 或 GUI 导入；原 Web 会话内存状态不是可迁移的项目文件。

桌面入口保持 `uv sync --group gui` 和 `uv run python -B -m dyntool_gui.app`。库用户无需安装 GUI 依赖。当前不发布新版本，不改变核心库公开入口、单位合同或存储格式。

## 范围合同

正式建筑振动展示通过 [展示示例](../usage/gui_building_showcase.md)生成完整合成项目，旧桥梁和通用占位演示保持原行为。多样本图新增已有 OTOVL 数据的下拉来源，模型对比图使用循环颜色和真实样本图例；默认项目启动和保存合同不变。

处理、预览、绘图与导出统一区分未冻结的请求和已冻结的 UID 范围。内部请求以 `None` 表示尚未解析，空元组表示已解析但没有样本。筛选零匹配、空子集和冻结空范围均返回中文错误或预检缺口，不回退到全部样本。全量操作必须明确选择全部样本。

运行态尚未恢复时，处理请求保留未解析状态；恢复完成后解析一次并冻结，不把恢复前的空范围误当成全量。已经冻结的空范围即使后来切换当前范围也仍为空。

## 批次报告与中止

绘图请求先冻结控件选择，再写回范围。普通项目恢复后首次切换到多样本图时，自动填充已保存的子集目标，同步范围刷新不再将请求改回旧模式。

GUI 汇总核心库每个 UID 的 `BatchOperationReport`，保留原始失败原因。成功数只统计成功样本，已有结果且不覆盖时计入跳过；前置数据缺失也计入跳过。界面同步展示成功、跳过、失败和未执行数量。非严格模式的样本失败标为部分失败，不能显示为全部成功。

后台任务收口后，排队的旧进度信号不得覆盖终态报告。该合同使用真实 QThread 验证，包含严格失败和非严格失败两种情况。来源读取异常不能被静默解释为数据缺失。

严格失败或协作式中止保留前序已完成结果，并同步能力摘要与数据脏状态。未运行的后序样本计入未执行；不提供整批回滚。核心库抛出的仓库级或未形成可恢复报告的错误仍停止批次。

## 项目保存边界

项目 JSON 保存工作区描述、原始来源、摘要、子集配置和成功的分析仓库引用，不保存模型数组。“保存项目”（`Ctrl+S`）只保存描述；“保存分析数据”（`Ctrl+Shift+S`）保存完整主样本集，包括已有派生结果，不受当前处理范围或子集选择限制。

项目 JSON 使用 UTF-8 无 BOM 与 LF。先在目标目录写入完整暂存文件，再替换原文件；可捕获的序列化、写入或替换失败保留旧文件，清理暂存资源。窗口显示失败原因，并保留项目引用、未保存状态和上次保存时间，不显示保存成功。

首次保存分析数据时选择保存父目录，默认从项目目录开始，在所选位置创建 `analysis_data` 仓库，采用现有 `SET_SQLITE_H5` 与 SQLite v2 布局。首次目标须为空且不得与原始来源或原运行态仓库相同，不合并无关工程。后续沿用成功目标；失败后沿用本次重试目标。成功后项目状态变为未保存，需再保存项目以记录该引用。原始来源继续保留，不自动写回。

数据保存以单样本为提交单位。严格模式失败即停，前序提交保留；非严格模式继续可恢复的样本错误，仓库级错误停止。任务显示成功、失败及未执行数量，保留核心逐样本报告与原因。部分保存失败不登记新的成功引用，不清除数据脏状态；重新打开部分仓库仍能读取已提交样本，当前工作区可以重试。不提供整批回滚。空槽位沿用核心非空合并规则，不通过保存隐式删除。

另存前需要读取原仓库尚未加载的可保存槽位，因此首次保存大集合可能增加内存使用。保存使用后台线程，忙态覆盖线程收尾；期间禁用其他写任务和直接关闭，不提供强制中止。保存结果与任务反馈在主线程收口，排队旧进度不能覆盖终态。

GUI 摘要读取槽位存在索引，不提前加载数组；已加载数量反映实际内存状态，能力列表反映内存或磁盘中的真实槽位。手动保存使用接入页当前严格设置，并在任务启动前冻结该设置。

关闭、新建、打开项目、切换演示或导入替换现有主集前，分别检查真实运行态的数据脏状态与项目脏状态，提供保存、放弃、取消。数据保存异步完成且线程收尾后，才继续原动作；保存失败或取消目标选择时留在当前工作区。第二次提示取消不会清除第一次放弃选择对应的脏状态。导入清理后自动关闭仍经过此保护。

重新打开项目时，处理、绘图或保存需要运行态则优先从成功的分析仓库恢复，保留原始来源引用；已保存 CSV 导入项目即使原 CSV 遗失仍可恢复结果。成功仓库引用遗失或损坏时明确报错，不悄悄回退到原数据。没有新引用的旧 JSON 仍按原样本集来源恢复；旧 JSON 未保存的内存结果无法补回。引用沿用绝对路径，移动工程后需要保持引用可访问。

所有保存均不承诺强制结束进程或断电后的自动恢复。其他处理、绘图和导出 manager 的统一主线程结果写回，以及桌面安装包仍是后续工作。
