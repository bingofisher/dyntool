# GUI 前端架构与路线
稳定性：`Internal API`

本页用于固定 `src/dyntool_gui/` 当前有效的前端标准。若与 `docs/superpowers/specs/2026-04-24-*` 系列规格冲突，以 `2026-04-24` 规格为准；本页的职责是把这些规格收束为开发者日常可直接引用的统一口径，而不是保留历史探索稿。

## 当前标准

- GUI 继续采用 `PySide6 Widgets + QMainWindow + QDockWidget + QStackedWidget`
- 不修改 `dyntool` Public API
- 当前主导航固定为 `总览 / 导入与筛选 / 数据处理 / 图形绘制`
- `SUBSET / EXPORT` 不再作为主导航页面，只允许作为内部兼容别名或迁移中的状态对象存在
- 视觉 token 与 Qt/Matplotlib 主题 hook 统一由 `ThemeManager + ThemeTokens` 管理
- 4 页正式工作台统一使用页面头部组件，固定“标题 + 副标题 + 当前摘要”语气
- 底部任务面板统一承载任务、日志、问题、导出、审查等详细状态
- 中央工作区优先；右侧 facts panel 不再作为正式结构
- `2560x1440` 等 2K 横屏场景采用横向工作台密度：窄对象树、薄任务区、紧凑导航、低高度页头、中心表格/画布优先
- 页面主界面只保留摘要、主动作和结果主体；导入参数、子集筛选规则、处理参数、绘图渲染/保存设置等复杂配置必须进入真实对话框，不再在左栏平铺堆叠

## 全局壳层

当前有效的窗口壳层固定为三层：

1. `项目上下文条`
2. `主导航条`
3. `当前页工具栏`

正式页面头部固定为：

- 页面标题
- 页面副标题
- 当前摘要

页面头部只承载“本页职责和当前状态”，不承载底部任务面板的详细日志、错误清单和长任务记录。

## 2K 横屏工作台合同

当可用屏幕宽度不小于 `2200` 且高度不小于 `1200`，或窗口宽高比不小于 `1.65` 时，GUI 进入横屏工作台布局口径。该口径只调整 `src/dyntool_gui/` 内部展示职责，不改变 `dyntool` Public API、存储格式、单位语义或 4 页主导航。

- 左侧对象树是窄导航栏，默认目标宽度为 `170-180px`，最大宽度不超过 `220px`
- 底部任务区是薄监控区，默认目标高度为 `96-112px`，详细日志由用户手动展开
- 顶部 4 页导航按钮高度不超过 `30px`
- 统一页面头部使用横向单行摘要栏，高度不超过 `64px`
- 导入与筛选页的上方导入链路是横向控制带，高度不超过 `240px`
- 数据处理页和图形绘制页的左侧配置栏最大宽度不超过 `320px`
- 图形页底部结果页签高度不超过 `136px`，不得挤压中央画布
- 页面空态只允许短状态句，不允许把“后续轮次接入”“占位”等历史文案作为正式用户主流程内容

主工作区固定为：

- 左侧：全高对象树
- 中央：当前页主体工作区
- 底部：默认折叠的任务面板

禁止继续使用下列历史口径：

- 6 页主导航
- 独立“交付”主页面
- 独立“筛选与子集”主页面
- 右侧 facts panel 作为正式布局组成
- 在页面主结果区堆放耗时、最近动作、推荐下一步、输出目录等任务摘要

## 页面职责

### 总览

- 只展示项目上下文、当前主样本集摘要、当前范围摘要、最近状态摘要
- 默认隐藏对象树
- 不承担复杂参数编辑、结构化筛选、处理执行或绘图配置

### 导入与筛选

- 承担样本/样本集接入、结构化检查、字段发现、筛选规则构建、数据预览、子集创建与集合组合
- 这是当前唯一承载“筛选与子集”语义的正式页面
- 导入参数必须通过“导入参数”对话框承载，主界面只保留接入模式、来源路径、选择来源和导入主动作
- 子集筛选正式采用论文搜索式布尔查询树：根节点和子组使用 `and / or / not`，叶子谓词使用 `in / not_in`、`= / != / > / >= / < / <=`、`contains / not_contains`、`exists / not_exists`
- `筛选规则` 对话框必须使用可增删规则列表组织条件，支持添加条件、添加分组、复制、删除和排序；字段候选来自当前 session，metadata 分类字段必须提供候选值提示，不得恢复固定 3 条顶层条件加 2 条二级条件的槽位式界面。
- 查询字段路径只允许 `uid`、`alias`、`metadata.<field>`、`data.<slot>`、`result.<name>`；`metadata.` 面向元数据字段，`data.` 面向原始或派生数据槽位，`result.` 面向评价结果和结果表可用性
- 子集筛选规则编辑器必须通过“筛选规则”对话框承载，子集名称、说明和动态/冻结保存动作必须通过“保存子集”对话框承载；页面左栏只显示规则摘要、保存摘要和预览/保存/设为范围动作
- 排序、分页、列过滤属于数据预览状态，不属于可持久化的筛选规则；`preview_rows` 只是界面抽样行，不得作为完整命中集合
- 子集保存必须区分界面预览与完整命中 UID：动态子集保存查询定义和完整命中 UID，冻结子集保存并使用 `resolved_uids`

### 数据处理

- 只负责处理与评价，不混入导入与筛选语义
- 优先消费全局 `current_scope`
- 主区负责方法选择、执行入口和结果浏览；范围目标、临时 UID、严格/覆盖开关、动作专属参数和预览字段进入“处理参数”对话框
- 执行前由 `ProcessingManager` 按动作所需数据槽生成处理范围计划；缺少前置数据的样本不进入库层批处理，跳过数量进入处理摘要、底部日志和问题列表
- 任务进度、错误详情、批处理统计统一进入底部任务面板

### 图形绘制

- 只负责 `PlotDataset -> PlotTheme -> plotter` 主链
- 页面主体固定为 `左侧配置 + 中央图形预览`
- 右侧 facts panel 已从正式结构中移除
- 左侧配置只保留绘图模式、来源范围和渲染/保存/补算入口；主题路径、点数上限、保存模式和保存格式进入“绘图设置”对话框
- 绘图模式、来源类型、来源名称、样本、范围、点数上限、主题和保存模式点选后必须立即刷新图形摘要、补算入口和保存按钮；渲染成功时写入 `PlotRequestSnapshot`，当当前设置与画布快照不一致时，保存按钮和“导出当前图”入口都必须拒绝执行。
- 图形页只暴露 plotting 正式 schema 口径，不把运行时字段冒充 TOML schema

## 对象树与状态边界

对象树当前标准结构以 `2026-04-24` 规格为准，开发口径固定为：

- `当前主样本集`
- `子集集合`
- `其他集合`
- `图形记录`
- `导出记录`

`ProjectSession` 是唯一会话状态源，负责保存：

- 项目上下文
- 当前主样本集引用
- 当前范围 `current_scope`
- 导入状态
- 筛选/子集状态
- 处理状态
- 绘图状态
- 底部任务面板所需摘要

页面组件只负责收集输入、发起请求、显示摘要，不直接拼接底层业务调用细节。

## GUI v2 操作管线

GUI v2 主线固定为 `点选状态 -> 命令快照 -> 管线节点 -> 统一反馈/审计`，属于 `src/dyntool_gui` 的 `Internal API` 合同。

1. 点选状态：对象树、表格行、下拉选择和页面焦点只更新 `GuiSelectionSnapshot` 与对应工作区本地输入。
2. 命令快照：主流程按钮触发时读取当前选择、当前范围、参数和 manager busy 状态，形成不可变的 `GuiCommandSnapshot`。
3. 管线节点：`ImportManager / ProcessingManager / PlotManager / ExportManager` 只消费命令快照或由快照派生的请求对象，再生成导入、处理、绘图或导出管线节点。
4. 统一反馈/审计：所有结果写回 `ProjectSession` 的任务、日志、问题、导出记录和审查记录；审计报告读取 `command_snapshots / feedback_events / feedback_metrics`，用于发现反馈矛盾，不反向驱动业务。

该管线要求页面点击与业务执行解耦：点选子集只改变当前选择或当前范围，不能暗中触发处理、绘图或导出；主流程执行必须能从命令快照追溯到当时的页面、范围、参数和 manager busy 状态。

## 全局忙态与关闭保护

- `MainWindow` 的全局忙态以 `ImportManager / ProcessingManager / PlotManager / ExportManager` 的活动线程和会话忙态共同判定。
- manager busy 是 GUI 内部全局互斥事实源：导入、处理、绘图、导出任一 manager 处于运行或线程收尾时，处理和导出这类会写回主样本集的任务入口必须拒绝启动，并使用“当前已有后台任务正在运行或收尾，请等待完成。”作为统一失败口径。
- `ImportManager.start_operation()` 必须自行拒绝重复启动；按钮禁用只作为交互层提示，不能作为后台任务互斥的唯一防线。
- 状态栏“当前任务”和全局进度条必须在 manager `state_changed` 后刷新；任务结果已经写回但线程尚未 `_cleanup()` 时，仍视为后台收尾中。
- `中止当前任务` 只暴露给可安全中止的导入和处理任务；处理任务采用协作式中止，请求后页面按钮改为“正在中止...”并等待下一个安全检查点；处理写任务必须能枚举 UID 并按 UID 分块执行，无法枚举 UID 的运行态必须给出中文失败反馈，不得回退为不可中止的全量写调用；绘图、导出任务不提供强制中止入口，等待线程自然完成。
- 关闭主窗口时，导入任务继续沿用原有清理保护；其他后台任务运行中必须阻止直接关闭，并提示用户等待完成或先中止可中止任务。

## 审计报告结构

`src/dyntool_gui.audit` 的报告 JSON 属于 GUI `Internal API`。旧字段 `actions / screenshots / dialogs / issues` 保持兼容；新增字段用于自动发现主链反馈矛盾：

- `workflow_metrics`：记录当前页面、当前范围、各 manager busy 状态和主入口 enabled 状态。
- `layout_metrics`：记录主工作区关键区域的矩形、可见性、面积和窗口占比，用于判断画布或表格是否成为页面主体。
- `feedback_metrics`：记录状态栏任务文本、全局进度条显隐、底部任务/日志/问题/导出行数和活跃对话框标题。
- `command_snapshots`：记录检查点对应的 `GuiCommandSnapshot`，包括选择状态、当前范围、任务反馈和入口启用状态。
- `feedback_events`：记录主链检查点、反馈变化和审计事件，用于串联“点击后发生了什么”。
- `rule_snapshots`：记录当前子集规则树、辅助条件、排序和分页输入。
- `button_state_snapshots`：记录用户可见按钮 enabled 状态、禁用原因、禁用原因来源、可见性和按钮区域。
- `plot_consistency_snapshots`：记录当前绘图设置、已渲染快照、保存可用性和不一致原因。
- `cancel_snapshots`：记录导入和处理任务的 busy、cancellable 与 cancel_requested 状态。
- `consistency_issues`：只记录反馈矛盾，例如后台忙碌但主执行入口仍可用、后台忙碌但状态栏进度不可见、后台空闲但状态栏仍显示忙碌。

## 实现分层

| 层 | 责任 | 说明 |
|---|---|---|
| `MainWindow` | 工作台外壳 | 负责三层壳层、Dock、菜单与全局动作 |
| `ProjectSession` | 唯一状态源 | 管理跨页状态、当前范围与各模块摘要 |
| `Manager` | 动作执行 | `ImportManager / ProcessingManager / PlotManager / ExportManager` 负责后台任务与状态写回 |
| `Workspace Widget` | 页面交互 | 负责参数输入、请求发射、主区摘要与结果展示 |
| `ThemeManager` | 唯一视觉出口 | 统一 Qt Widgets 与 Matplotlib 的主题 token 和 hook |

## 当前需要明确避免的误读

- 不能再用“文档里有 6 页，所以代码应该做 6 页导航”来评审当前 GUI
- 不能把 `SUBSET / EXPORT` 是否仍存在内部状态对象，误判为“必须恢复成独立页面”
- 不能把历史设计稿里的右侧信息栏，当成当前可接受的正式结构
- 不能把 `preview_rows` 当成完整命中集合；完整命中 UID 必须从子集解析结果或保存的 `resolved_uids` 读取

## 迭代路线

当前迭代顺序以 `2026-04-24-gui-iteration-plan-by-sequence.md` 为准，开发者摘要如下：

1. 清理旧 `SUBSET / EXPORT` 导航残留、旧动作别名和重复 handler
2. 固定全局三层壳层与 Dock 行为
3. 重构对象树、点选状态与命令快照模型
4. 重构导入与筛选页的查询树、完整 UID 命中和子集保存合同
5. 收口数据处理页
6. 收口图形绘制页
7. 统一底部任务面板、文案、验证与回归
